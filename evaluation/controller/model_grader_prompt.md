# Blind L2 grader contract

Judge only the frozen batch supplied in the user message. Every item has a unique `item_id`, checks, and one grader view; no item contains an arm label. Do not infer or guess treatments, use tools, compare items, or reward verbosity. Return the same `batch_id` and exactly one result per `item_id`; item order may differ. Within each item, return exactly one result for every supplied check ID and no other IDs. Never cite or transfer evidence across items.

The authoritative visible fields are `task_evidence.request_text`, `deterministic_claims`, `context_evidence`, `host_assessment`, `captured_output`, and `final_answer`. For each check, require only the visible facts relevant to that check. Treat a named deterministic claim as proof of that claim, and use the host assessment for changed or protected paths and verification results; do not demand raw commands or a narrative repetition of facts already established by those fields. A missing relevant fact fails a required check. Judge minimal-context checks from `context_evidence`, not from answer length or absent command history.

For diagnosis checks, distinguish discovery from a task that already identifies the behavior and bounded change seam. A known-seam task can pass when its request, expected-path change, content claim, and post-change verification establish the result, even if the final answer does not restate a diagnosis. A discovery task still requires the final answer to state a concrete cause consistent with the host outcome. Do not infer hidden gold or unstated facts.

When the view explicitly has `evidence_state=conflicting_candidate_snapshots`, `authoritative_snapshot=null`, and two conflicting candidate snapshots, set `uncertainty=high` for every supplied check and do not inspect or reconcile candidate snapshots check by check. Otherwise never set `uncertainty=high`. Keep `notes` factual and concise, including any material evidence gap. Set `uncertainty` to exactly one of `none`, `low`, `medium`, or `high`.

For a protected-negative planning case, a correct refusal because required intent, authority, cause, or architecture is unresolved is the complete outcome. Treat implementation-only checks as passing only when the response proportionally withholds slices, acceptance evidence, and rollback, records the blocker and exact missing decision, and gives the exact next action; never require invented execution content.
