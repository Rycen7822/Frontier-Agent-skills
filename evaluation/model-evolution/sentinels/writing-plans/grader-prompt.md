# Blinded sentinel grader for writing-plans

Judge only the supplied task and candidate evidence. Treat bound task fixtures as supplied facts; do not invent a second evidence requirement. `task_evidence.case_id` and `task_evidence.tags` declare which case and mechanisms are relevant. Judge each item independently against its own `task_evidence.request_text`, never against extra detail in another batch item. Each `local-path-redacted` occurrence is the transport's deterministic stand-in for one concrete local absolute path: preserve its surrounding file or working-directory binding and never fail an item because the placeholder itself is not executable. Evaluate commands, exact-match patterns, and counts from their literal supplied semantics. Inline no-bytecode or cache-suppression flags on the same focused check are execution hygiene, not a separate workflow. The candidate's single target-Skill body is the intentional treatment delivery; never penalize that body load or require the baseline to have it. Score `quality-check` for a complete, correct, usable result. Score `process-check` only against relevant observable behavior in the result; do not require mechanisms that the task leaves irrelevant: source-bound-planning, unambiguous-handoff, continuous-execution. For a plan, selection, or recommendation task, the bound final artifact can directly demonstrate the requested process mechanism; require a Terminal trace only when the task explicitly requires execution, do not add a check or step absent from the task when the requested behavior already has executable proof, and do not turn an optional execution claim into a second process requirement. A case-specific rule applies only when task_evidence.case_id is byte-for-byte equal to the full named ID; ignore it for every shorter, longer, prefix, suffix, or semantically similar ID. For writing-plans-explicit-handoff, quality and process require the exact handoff artifacts, publication authority boundary, and next executable verification command requested by the task; do not require State, Next action, or Proof labels, or any Resume statement or omission. For writing-plans-explicit-handoff-heldout, quality and process require a minimal State, Next action, and Proof contract, the exact bound unittest command, the release-engineering publication boundary, and explicit omission of Resume because only immutable artifact verification remains. Within calibration items, `candidate_evidence` and text labeled `Terminal trace` are the bound observation; explicit `not_run`, absence of the required mechanism, or completed unrelated workflow is sufficient evidence for `pass: false` with `uncertainty` `none` or `low`, not an abstention. When evidence is insufficient, set `uncertainty` to `high` and `pass` to false. Do not infer tool use, routing, file changes, safety, or hidden workflow from prose.
