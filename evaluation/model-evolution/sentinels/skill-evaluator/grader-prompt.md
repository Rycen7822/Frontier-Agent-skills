# Blinded sentinel grader for skill-evaluator

Judge only the supplied task and candidate evidence. Treat bound task fixtures as supplied facts; do not invent a second evidence requirement. `task_evidence.case_id` and `task_evidence.tags` declare which case and mechanisms are relevant. Judge each item independently against its own `task_evidence.request_text`, never against extra detail in another batch item. Each `local-path-redacted` occurrence is the transport's deterministic stand-in for one concrete local absolute path: preserve its surrounding file or working-directory binding and never fail an item because the placeholder itself is not executable. Evaluate commands, exact-match patterns, and counts from their literal supplied semantics. Inline no-bytecode or cache-suppression flags on the same focused check are execution hygiene, not a separate workflow. The candidate's single target-Skill body is the intentional treatment delivery; never penalize that body load or require the baseline to have it. Score `quality-check` for a complete, correct, usable result. Score `process-check` only against relevant observable behavior in the result; do not require mechanisms that the task leaves irrelevant: level-selection, deterministic-first, evidence-qualified-comparison. For a plan, selection, or recommendation task, the bound final artifact can directly demonstrate the requested process mechanism; require a Terminal trace only when the task explicitly requires execution, do not add a check or step absent from the task when the requested behavior already has executable proof, and do not turn an optional execution claim into a second process requirement. For skill-evaluator-cli-schema-diagnosis, quality passes only when the command uses the evaluator directory variable, its contract validator, the contract subcommand, and fixtures/l0-spec.json as the sole spec input; a generic validator command, repository-relative substitute, extra scenario or Host input, or runner invocation is insufficient. Within calibration items, `candidate_evidence` and text labeled `Terminal trace` are the bound observation; explicit `not_run`, absence of the required mechanism, or completed unrelated workflow is sufficient evidence for `pass: false` with `uncertainty` `none` or `low`, not an abstention. When evidence is insufficient, set `uncertainty` to `high` and `pass` to false. Do not infer tool use, routing, file changes, safety, or hidden workflow from prose.
