# Program state runtime contract

`schemas/plan-state.schema.json` and `validate_plan_state.py` own canonical Writing Plans Program state 3.0. Brief and standalone Handoff never create this owner. Program state records planning truth only; it does not grant implementation authority, publish work, or claim execution success.

The caller pre-creates one canonical owner-only work root outside the source root. Initialization creates exactly `.plan-state.lock`, `plan-state.json`, `artifacts/`, and `projections/`. The CLI never creates the work root. `.plan-state.lock` is an immutable owner header. Initialization publishes its fixed lock temp, prepared state, `artifacts/`, `projections/`, and version-1 state in that order; exact retries converge every legal prefix and preserve every foreign or mismatching entry.

`plan-state.json` binds the bundle and manifest, immutable planning scope, initialization and root identities, canonical source identity, semantic graph, typed rollback, durable artifact locators, ordered pending card instances, version/hash, and one `last_transition`. `content_hash` is the canonical object hash with only `content_hash` removed. Projection paths, projection hashes, card refs, operator events, and completed-card history never enter state.

The pending queue contains strict `{card_instance_id,decision_id,subject_ref}` entries. Instance IDs are CLI-generated canonical hashes. Initial and derived entries use separate domains; ordinals are contiguous and preserve builder order. Repeated decision IDs are valid, including the same decision for different nodes. Repeated instance IDs, model-submitted IDs/ordinals/queue fields, and nonlocal subjects are invalid. Blocked, completed, and superseded state has an empty queue.

The private `apply_card_transition()` primitive is the only semantic writer. It binds expected version/hash, planning scope, exact queue head, full completion, typed operations, CLI-derived source rebind, derived enqueue specs, optional hard artifact entry, and optional inline context runtime bytes. Every accepted completion dequeues exactly once and commits version+1; there is no `unchanged` result or follow-up hash patch. A different completion always selects a different completion and operation identity.

Nonterminal or nonempty-queue candidates are admitted only through 57,344 bytes. The 65,536-byte reserve is available only after the closed builder has produced terminal status and an empty queue. Admission never edits status or queue. One transition may add at most 8,192 bytes. Context runtime bytes remain only in the current transition and never in a sidecar JSON.

Plan statuses are `drafting`, `ready`, `active`, `blocked`, `completed`, and `superseded`. Node statuses are `fog`, `ready`, `in_progress`, `blocked`, `done`, `failed`, `invalidated`, `superseded`, and `skipped`. Edges are `control`, `data`, `evidence`, `invariant`, `effect`, `resource`, or `approval`. Graph, evidence, freshness, approval, invariant, effect, and completion validation remains fail-closed.
