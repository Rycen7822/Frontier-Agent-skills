# Collaboration and working state

Use for multiple writers, cross-context work or temporary resources with nontrivial ownership.

Delegate only when permitted and a bounded independent task provides enough benefit to cover coordination and context costs. Keep critical dependent work local. Give the other worker the objective, relevant source, current user constraints, allowed writes, completion condition and needed verification evidence; avoid ceremonial contracts or compulsory role counts. On follow-up or resume, carry forward still-applicable constraints and incorporate later changes to scope or requirements. Isolate overlapping writes and check the delivered artifact and decisive evidence when integrating, resolving contradictions against source. A worker's completion summary alone does not establish completion.

For authorized, worthwhile parallel work, start only tasks whose prerequisites are satisfied. Before integrating into a shared target, recheck its current state; refresh any integration evidence affected by changes since the worker's check.

Reuse the repository or host's existing state record. When recovery needs one and none exists, keep a single compact note with the current objective, settled decisions, completed work, unresolved issue and next action. Update when those facts change, not on a timer. Recheck changed or uncertain facts on resume; do not replay the entire task.

Place scratch work in the user-selected temporary location. Track ownership only as far as needed to preserve user work and clean up safely. Untracked and ignored files are not automatically disposable. Retain useful results and stop only resources created for this task. Avoid forced work-in-progress commits or another log format.

At a stop, handoff or completion, account for workers and resources started for this task. Stop, retain or transfer them within existing authorization, preserving user sessions and unrelated resources. When ongoing work could affect the next action, confirm a requested stop from observable host or process state; sending the request does not prove execution stopped. Report unavailable state as unknown instead of claiming a successful stop.
